# ADR-0001: 백엔드 없는 정적 사이트 + 가벼운 PWA

- 상태: 제안됨
- 날짜: 2026-11-20
- 근거: [PRD v0.6](../prd/PRD-v0.6.md) §1, §7(Offline), §8 F1·F5·F6·F7, §11, §15
- 관련: [ADR-0002](0002-four-sheet-data-model-and-csv-build.md), [ADR-0005](0005-static-site-generator-astro.md), [ADR-0006](0006-hosting-github-pages.md)

## 배경

- 수익이 없고 시간 예산도 없는 학부생 1인 프로젝트다(§1, §15). 운영할 서버, 데이터베이스, 계정 시스템을 둘 여유가 없다.
- 데이터는 창업자가 시트에서 직접 고치고 다시 배포한다(F5 워크플로). 사용자 쓰기 기능은 모두 외부 도구로 처리한다. 정정·추가는 Google Form, "Was it as listed?"는 분석 이벤트(F6)를 쓴다.
- 위치 좌표는 기기를 떠나면 안 된다(F1, §11). 거리 계산을 기기에서 하면 서버가 필요 없다.
- 홈 화면 추가와 오프라인 화면이 필요하다(§7, §11). 동시에 v0.2 CTO 리뷰는 service worker가 오래된 데이터를 보여 주면 "정확성"이라는 핵심 가치가 무너진다고 지적했다.

## 결정

1. 사이트는 **빌드 시 생성한 정적 파일만** 배포한다. 서버 코드, API, 데이터베이스, 로그인이 없다.
2. 동적 동작(위치·거리 정렬, 필터, URL 상태, 공유 목록 `/list?c=`, 루트 언어 이동, F6 응답 기억)은 **브라우저의 작은 스크립트**로 한다.
3. 외부로 나가는 쓰기는 두 가지뿐이다. Google Form 링크(F5)와 GoatCounter 이벤트(F6, Directions; [ADR-0004](0004-analytics-goatcounter.md))다.
4. PWA는 **가볍게** 만든다.
   - `manifest.webmanifest`: 홈 화면 추가용
   - service worker: **네트워크 우선**. 온라인이면 항상 네트워크 응답을 보여 주고, 오프라인일 때만 캐시를 쓴다. 캐시도 없으면 오프라인 화면을 보여 준다.
   - 미리 캐시(precache)는 오프라인 화면과 필수 정적 자원만 한다. 데이터 페이지는 방문할 때만 캐시한다.
   - 다른 출처 요청(GoatCounter, Google Form, Google Maps 길찾기)은 가로채지 않는다.
   - 배포할 때마다 캐시 이름(빌드 id)을 바꾸고, 이전 캐시는 지운다.

## 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| 작은 백엔드(서버리스 함수 + DB)로 F6·정정 저장 | 운영·비용·보안 부담이 생긴다. 쓰기 양(주 몇 건)으로는 정당화되지 않는다 |
| service worker 없음(CTO v0.5 리뷰 제안) | 가장 단순하지만, PRD가 오프라인 화면과 홈 화면 추가를 요구한다(§7, §11). 네트워크 우선이면 온라인 사용자가 오래된 데이터를 볼 일이 없어 리뷰의 우려가 줄어든다 |
| 캐시 우선(cache-first) / stale-while-revalidate | 온라인인데도 이전 데이터가 보일 수 있다. 정확성 가치와 맞지 않는다 |
| PWA 플러그인(vite-plugin-pwa 등) | 동작이 단순해서 직접 쓴 50줄 정도의 `sw.js`가 더 읽기 쉽다. 플러그인 설정과 업그레이드를 따로 익히지 않아도 된다 |

## 결과

**좋은 점**
- 운영 비용이 0에 가깝다. 장애 지점은 호스팅뿐이다.
- 좌표가 서버로 가지 않는다는 개인정보 약속을 구조적으로 지킨다.
- 오프라인에서도 한 번 본 페이지는 열린다.

**나쁜 점 / 감수할 것**
- 데이터 변경은 다시 배포해야만 반영된다(F5에서 이미 받아들인 조건).
- 필터 결과 URL(`?f=…`)은 클라이언트에서 그린다. 그래서 크롤러와 JS를 끈 사용자는 필터 전 목록만 본다. 언어별 제목·설명은 페이지 단위로만 다르다(§10).
- service worker 버그는 사용자 기기에 남을 수 있다. 문제가 생기면 등록을 해제하는 "kill switch" 버전(빈 fetch 핸들러 + 캐시 삭제)을 배포할 수 있게 둔다.
- 공유 목록 SC-04의 내용은 빌드에 포함된 데이터로만 그린다. 그래서 오래된 링크의 id가 없으면 F7 규칙대로 건너뛴다.
