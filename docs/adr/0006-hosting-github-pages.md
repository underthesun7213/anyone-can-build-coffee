# ADR-0006: GitHub Pages + GitHub Actions로 호스팅·배포한다

- 상태: 승인됨 (2026-11-27, 창업자)
- 날짜: 2026-11-20 (웹 사실 확인일 동일)
- 근거: [PRD v0.6](../prd/PRD-v0.6.md) §1(수익 없음, 광고는 나중에 검토), §7(404), §11("free static hosting on a subdomain of the founder's personal domain"), §8 F5(수정 후 재배포)
- 관련: [tech-stack.md](../architecture/tech-stack.md) §6, [ADR-0002](0002-four-sheet-data-model-and-csv-build.md), [ADR-0005](0005-static-site-generator-astro.md)

## 배경

- PRD는 무료 정적 호스팅과 개인 도메인의 서브도메인만 정했다.
- 창업자는 정정을 받을 때마다 다시 배포한다(F5). 그래서 배포 횟수 한도가 중요하다.
- 레포와 PR 흐름은 이미 GitHub에 있다.

## 확인한 사실 (2026-11-20)

| | GitHub Pages | Cloudflare Pages | Netlify Free |
|---|---|---|---|
| 한도 | 사이트 1 GB, 대역폭 월 100 GB(소프트), 시간당 10회 빌드 소프트 한도(커스텀 Actions 배포는 해당 없음), 배포 10분 타임아웃 | 월 500회 빌드, 동시 1개, 파일 20,000개 | 월 300 크레딧. 프로덕션 배포 1회 15 크레딧, 대역폭 GB당 20 크레딧 |
| 서브도메인 | CNAME, HTTPS 강제 가능 | 외부 DNS CNAME 가능 | 가능 |
| 조건 | 무료 플랜은 공개 레포만. 온라인 사업용 무료 호스팅이 아님. 방문자 IP를 보안 목적으로 기록 | 별도 계정 | 크레딧 소진 시 동작은 미기재 |

출처: tech-stack.md §6의 [15]~[24].

## 결정

1. 호스팅은 **GitHub Pages**로 하고, 배포는 **GitHub Actions 커스텀 워크플로**(`actions/upload-pages-artifact` + `actions/deploy-pages`)로 한다.
2. 워크플로는 두 개다.
   - `ci.yml`: `pull_request` 때 실행한다. 데이터 검증 → `astro check` → 빌드 → 빌드 후 확인(`internal_note` 노출 검사)을 하고 배포는 하지 않는다.
   - `deploy.yml`: `main`에 push할 때와 `workflow_dispatch`(수동) 때 실행한다. 같은 단계 뒤에 배포한다. 검증이 실패하면 배포 단계까지 가지 않는다.
3. 커스텀 도메인은 창업자 개인 도메인의 서브도메인 하나로 하고, DNS에 CNAME을 둔다. HTTPS 강제를 켠다.
4. `404.html`은 Astro의 `src/pages/404.astro`로 만든다. 언어를 알 수 없으므로 두 언어로 쓴다.
5. 개인정보 고지(SC-05)에 호스팅 업체(GitHub)가 방문자 IP를 보안 목적으로 기록한다는 내용을 넣는다.

## 고려한 대안

| 대안 | 기각/보류 이유 |
|---|---|
| Cloudflare Pages | 한도가 넉넉하고 `_headers`(커스텀 헤더)를 지원한다. 하지만 계정과 연동이 하나 더 필요하다. 지금 필요한 기능 중 GitHub Pages로 안 되는 것이 없다. **이전 1순위 대안**: 광고 도입 등으로 GitHub Pages 이용 조건이 맞지 않게 되면 옮긴다 |
| Netlify Free | 배포 1회당 15 크레딧이라, 배포만으로 월 약 20회면 크레딧 300이 끝난다(계산값). 잦은 정정 배포와 맞지 않는다 |
| Vercel | 레포에 Vercel GitHub 연동이 이미 연결돼 있어 PR마다 미리보기 배포가 만들어지고 있었다(2026-11-27 확인). 창업자가 GitHub Pages로 결정했으므로 쓰지 않는다. 연동은 해제한다(아래 "후속 조치") |

## 결과

**좋은 점**
- 코드, PR, CI, 호스팅이 한곳에 있다. 같은 검증이 PR과 배포에서 똑같이 돈다.
- 이 규모에서는 한도에 걸릴 일이 사실상 없다(추정: 수백 페이지, 주간 방문 100 목표).
- 검증 실패 시 이전 배포가 그대로 남는다. 롤백은 커밋 되돌리기 후 재배포다.

**나쁜 점 / 감수할 것**
- 레포가 공개여야 한다. 그래서 `internal_note` 같은 비공개 값이 레포에 들어오면 안 된다(ADR-0002).
- 커스텀 응답 헤더(캐시 제어, 보안 헤더)와 서버 리다이렉트를 설정하는 방법이 확인한 문서에 없다(지원하지 않는 것으로 추정). 언어 이동은 클라이언트 스크립트로 한다.
- 광고를 붙이면 "온라인 사업용이 아님" 조건과 부딪칠 수 있다. 그때 호스팅을 다시 판단한다.

## 후속 조치

- **Vercel 연동 해제:** 이 레포에는 Vercel GitHub 연동이 연결돼 있어 PR마다 미리보기 배포와 봇 코멘트가 생긴다. 배포 경로가 둘이 되지 않도록 Vercel 프로젝트 설정 또는 GitHub의 연동 설정에서 이 레포의 연결을 해제한다. 계정 설정이므로 창업자가 직접 한다.
